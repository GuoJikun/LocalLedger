# 净账（LocalLedger）— 执行计划

> 本文件把 `规划.md` 的设计拆成可执行的任务。技术栈已确认：**Tauri 2 + Vue 3 + Rust + SQLite**。
> 目标平台：**Windows / macOS / Linux** 三端同源，CI 从第一天起覆盖三平台。

---

## 一、前提与假设

| 项 | 取值 | 备注 |
|---|---|---|
| 技术栈 | Tauri 2 + Vue 3 + TypeScript + Rust + SQLite | 已确认 |
| 平台 | Windows 10+ / macOS 12+ / Linux（deb + AppImage） | 一套代码，三端打包 |
| MVP 形态 | 单账本、单设备、完全离线 | 已确认；数据结构预留多账本 |
| 局域网同步 | V1.x，基于变更日志的增量同步 | 元数据字段在 MVP 就落地 |
| 数据原则 | 本地 SQLite 为唯一数据源；离线优先；无账号、无埋点 | 网络访问需显式开启 |

## 三、详细任务拆解

### M0 — 脚手架（跨平台打底）

- [ ] 初始化 Tauri 2 + Vue 3 + TypeScript 项目骨架
- [ ] 配置三平台应用标识、图标、窗口属性
- [ ] 打通 Rust 侧获取 `app_data_dir`，确认三端路径正确
- [ ] 建立跨平台 CI 矩阵（`windows-latest` / `macos-latest` / `ubuntu-latest`）
- [ ] 基础布局与主题（浅色/深色、中文界面）

**验收**：三平台均能构建并启动空窗口；CI 三平台任务通过。

### M1 — 数据底座（同步字段现在就埋好）

- [ ] 引入 SQLite（`rusqlite`）与数据库迁移机制
- [ ] 建表：`accounts` / `transactions` / `categories` / `category_rules` / `sync_changes` / `devices` / `meta`
- [ ] `transactions` 加 `UNIQUE(source, external_id)`，金额字段用 INTEGER（分）
- [ ] 业务表统一加 `updated_at / device_id / version / deleted`
- [ ] 定义 `Repository` trait 并实现 SQLite 版本
- [ ] 交易、分类的 Tauri 命令（CRUD）
- [ ] 设备 ID 生成并持久化到 `meta` / `devices`
- [ ] 写数据库层单元测试

**验收**：CRUD 测试通过；三平台数据库文件都在正确的数据目录生成；删除为软删除。

### M2 — 账单导入

- [ ] 通用导入管线：编码检测 → 跳过头部 → 列映射 → 解析 → 金额标准化 → 去重 → 分类 → 入库
- [ ] 支付宝解析器：GBK 解码、元信息行跳过、字段映射、交易状态处理
- [ ] 微信解析器：UTF-8 BOM、说明行跳过、字段映射、转账/红包/退款类型处理
- [ ] 用 Tauri dialog 插件做跨平台文件选择
- [ ] 导入结果反馈：成功条数、跳过条数、错误行明细
- [ ] 准备真实脱敏样例 CSV，写解析器回归测试
- [ ] 导入 UI（拖拽/选择文件、进度、结果）

**验收**：样例账单字段解析准确；同一文件重复导入不产生重复数据；错误行有明确行号与原因。

### M3 — 流水与分类

## 四、跨平台特别注意事项

| 事项 | 处理方式 |
|---|---|
| 路径 | 统一用 Tauri 的 `app_data_dir`，不硬编码 `C:\` 或 `/home` |
| 文件选择 | 用 `tauri-plugin-dialog` 原生对话框，遵守 macOS 文件权限 |
| 编码 | 账单编码来自文件本身与操作系统无关；GBK/BOM 检测必须跨平台可靠 |
| 金额 | 全链路用整数「分」，只在展示层格式化 |
| 时间 | 统一存 UTC 时间戳，展示按本地时区；账单日期以平台原始文本为准解析 |
| mDNS | 优先纯 Rust 实现避免系统服务依赖，必须保留手动 IP 兜底 |
| 打包签名 | macOS 需签名+公证；Windows 可选代码签名；先功能后签名 |
| UI 字体 | 中文界面在 macOS/Linux 需内嵌或指定中文字体回退 |
