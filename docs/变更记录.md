- 数据库层 11 个单元测试通过；实测三平台路径解析在 Windows 上正确（`%APPDATA%`）。

## M2 账单导入 — 2026-11-19

- 通用导入管线：字节读取 → UTF-8/BOM/UTF-16/GBK 编码检测 → 平台识别 → 跳说明行 → 表头列映射 → 逐行解析 → 金额标准化 → 去重 → 自动分类 → 入库。
- 支付宝解析器：GBK 解码、元信息行跳过、`交易号/收/支/金额/交易状态` 字段映射，非成功状态跳过。
- 微信解析器：UTF-8 BOM、说明行跳过、转账/红包/退款特殊类型处理。
- 金额按整数分精确解析，兼容 `¥` 与 GBK 编码产生的 `&#165;` 实体。
- `UNIQUE(source, external_id)` + 文件内去重保证重复导入幂等；默认分类规则按优先级自动套用。
- Tauri dialog 文件选择 + 原生拖放（含路径）；导入结果反馈成功/重复/跳过/自动分类与错误行号。
- 真实脱敏样例夹具与 19 个测试；命令层用 GBK 文件端到端验证。

## M2 修正 — 2026-11-19

- 支持支付宝导出为制表符（Tab）分隔的 CSV：按前 20 行自动选择 `,` / `\t` 分隔符。
- 表头识别兼容「交易订单号」（不再强制要求「交易号」列），兼容列名首尾空格。
- 交易单号优先取「交易订单号」，缺失时回退「交易号」/「商家订单号」；「备注」列并入交易备注。
- 新增用户实际表头夹具与回归测试，测试总数 24。
- 导入页新增「当前支持的账单表头」折叠面板，展示支付宝（逗号/Tab）与微信表头样例及列别名说明。
- 支付宝「收/支」列显式排除「不计收支」，跳过原因明确展示在导入结果中；回归夹具覆盖该类型。
- 交易时间解析容错增强：支持中文日期、单数字月日、无分隔紧凑格式、无秒数与带时区格式；无法识别时错误信息带出原始时间值。
- 表头判定收紧为「至少 3 列 + 关键字」，避免含关键字的说明行被误判为表头。
